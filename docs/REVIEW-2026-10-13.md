# Full Project Review - 2026-10-13 (post RUN-1, master @ 5def2b7)

Scope: whole-repo review cross-checked against github.com/frehan83-collab/AquaIntel
(local master == origin/master == 5def2b7, CI green on the last two commits,
release v2.3.0 published, repo is PUBLIC). Method: full R10 diff review +
project-wide scans (secrets, auth, CORS, rate limiting, raw SQL, blocking
calls, dependency pinning, test inventory, frontend hygiene, alembic chain,
git/PR state).

## Verdict

Merge-quality of RUN-1 work itself: good (CI-proven, honest, well-tested at
the touched seams). Project-level risk: MEDIUM - not because of the recent
commits, but because two protection layers (tier paywall, rate limiting)
look implemented in config yet are never enforced, and the public repo
carries 5,178 tracked test-artifact files.

## Findings by severity

### High

H1. Rate limiting is configured but inert (core/api.py:202-208).
    `Limiter(default_limits=["200/minute"], strategy="moving-window")`,
    `app.state.limiter`, and the RateLimitExceeded handler exist, but
    SlowAPIMiddleware is never added and zero routes use `@limiter.limit`.
    slowapi only enforces via middleware or per-route decorators, so nothing
    is actually limited. Impact: unauthenticated hammering of 296 routes,
    many of which call external APIs (SSB, BarentsWatch, Copernicus);
    `api_calls_per_day` tier quotas are also unenforced.
    Fix: `app.add_middleware(SlowAPIMiddleware)` (verify the key_func works
    for anonymous users), plus a regression test that a burst gets 429.

H2. Tier/paywall enforcement is dead code (core/auth.py:77-136, 345, 360).
    `TIERS` (free/professional/enterprise/investor with route allow-lists and
    api_calls_per_day), `check_tier_access`, and `require_tier` have ZERO
    callers outside auth.py. Billing tiers are priced (2,990-24,900 NOK/mo)
    but no route is gated server-side; every route is effectively public.
    Fix (pick one, honestly): (a) add an APIRouter-level dependency or
    middleware that calls check_tier_access on the request path, with
    tests; or (b) remove tier pricing/gating claims from the product until
    enforcement ships. Half-wired is the worst state.

H3. Repo hygiene: 5,178 `.hypothesis/` files are tracked in git even though
    `.gitignore` line 16 ignores them (committed before the rule existed;
    ignore does not untrack). Public-repo clone bloat + noisy diffs.
    Fix: `git rm -r --cached .hypothesis` + commit (history rewrite optional).

H4. R10 regression of its own honesty class (frontend/src/app/china-demand/
    page.tsx ~182 and ~415): the supplier note and the "Data Sources"
    footer render unconditionally, so while loading (or if the fetch fails
    entirely) they claim "SSB series unavailable - Norwegian export figures
    are shown from curated estimates" when nothing is shown at all.
    Fix: gate both blocks on `snapshot` presence (and treat fetch-error as
    its own state), e.g. `{snapshot && (<footer .../>)}`.


### Medium

M1. Liveness still keyed on rounded tonnage, contradicting the documented
    invariant ("never on a rounded tonnage"): country_routes.py
    `_china_provenance` (`result.get("monthly_series") or
    norway.get("tonnes_12m")`) and supply_demand_engine.py:596 keep the
    `or tonnes_12m` clause; tests/test_china_provenance.py
    `test_live_when_tonnes_present` even pins the contradicting behavior.
    Unreachable today (tonnes>0 implies series non-empty), but a future
    estimate fallback that fills tonnes_12m would silently re-introduce the
    bug. Fix: drop the `or` clauses; change the test to assert tonnes-only
    does NOT claim live.

M2. Untested changed routes: `/api/china/signals` and `/api/china/impact`
    got new provenance wiring but only `/api/china/demand` is tested. A
    regression in either would pass CI. Fix: add the two route tests (both
    degraded and live variants) mirroring the /demand tests.

M3. Brittle frontend liveness contract: china-demand page derives
    `norwayLive` via `String(norExp.data_source).startsWith("LIVE")`. Any
    wording change silently flips the copy. Fix: expose a structured
    `norway_exports_to_china.is_live` boolean (additive, allowed under
    API_SCHEMA_VERSION 1.1 policy; re-freeze openapi.frozen.json) and read
    that in the page.

M4. Badge quality mapping mislabels low-confidence real data as
    "Synthetic": DataQualityBadge.qualityFromProvenance falls through to
    "synthetic" for confidence < 0.4 unless source === "simulated" exactly.
    The newly-badged /price-outlook has a real confidence=0.3 degraded path
    (SSB unreachable -> NOK 75.0 fallback) that will render "Synthetic".
    Fix: map by provenance state (is_live false + degraded reason ->
    "degraded"), not confidence thresholds alone.

M5. Degraded snapshots are cached the full 2h TTL (china_demand.py:215-216)
    - honest, but recovery after an SSB outage takes up to 2 hours, and
    concurrent cold calls can double-fetch (no single-flight lock).
    Fix: shorter TTL (10-15 min) when monthly_series is empty; optional
    asyncio.Lock around the fetch.

M6. Stale PR/branches on GitHub: PR #2 ("Session 38: Wire
    welfare/NorKyst/PACE endpoints + ErrorBoundary sweep", 16 commits,
    branch claude/happy-curie) untouched since 2026-04-17 with mergeable
    UNKNOWN - six months behind master (RUN-1 alone added engines, a
    migration, and versioning). Plus branch claude/cool-cray (April).
    Fix: rebase-and-review or close; delete merged/stale branches.

M7. CHANGELOG drift: R10 entry says the badge uses `role="status"` but the
    shipped code uses `role="img"` (DataQualityBadge.tsx:45). One-line doc
    correction.

### Low / Nits

L1. supply_demand_engine.py:596 calls `snap.get(...)` unguarded while the
    line above guards `norway = (snap or {})` - inconsistent None-safety
    (latent AttributeError if the engine contract ever changes).
L2. Dead code: china_demand.py `get_top_suppliers` (no callers) still
    hardcodes "Norway data is LIVE from SSB table 08799"; either delete or
    fix. `get_supply_impact` docstring "Uses LIVE SSB price data" is wrong
    when degraded.
L3. DataQualityBadge: native `title` tooltip duplicates the custom tooltip
    (double tooltip on hover); `tabIndex={0}` has no visible focus ring
    (add focus-visible styling); many badges = many tab stops.
L4. DataProvenance.live(...) is pasted identically across ~40+ route
    call sites; the `_china_provenance` helper is the right direction -
    consider one shared helper per data domain, plus a cheap contract test
    that greps payloads for "LIVE" strings when provenance says degraded
    (regression net for the R10 bug class, engine-level nested claims).
L5. Frontend typing debt: 472 `any` usages and 79 eslint-disables in
    frontend/src; api.ts types exist - migrate hot pages first.
L6. docs/PLATFORM_STATUS.md is UTF-16 (breaks grep/diff tooling) -
    renormalize to UTF-8.
L7. Engine info logs do not include the live/degraded flag; no metrics
    (Prometheus) endpoint despite structlog + CorrelationID middleware
    being in place (both good).
L8. requirements.txt uses `>=` lower bounds only (fastapi has an upper
    bound - good); requirements.lock is used in Docker (good). Local dev
    (requirements.txt) and image (requirements.lock) can drift - note it.

## Positive observations

- RUN-1 delta-loop discipline: every change CI-proven, committed with
  evidence, docs (CHANGELOG/STATUS/AGENTS) updated in the same commit;
  OpenAPI frozen-contract testing; honest versioning (PLATFORM 2.3.0 /
  API_SCHEMA 1.1 + published GitHub release).
- Security fundamentals are mostly solid: JWT secret refuses to boot in
  prod without a strong secret; bcrypt password hashing; hashed API keys
  returned once; admin router hard-gated with `Depends(require_admin)`;
  explicit CORS origins via env; SecurityHeaders/CorrelationID middleware;
  no secrets committed (.env.example is empty values); no raw f-string SQL
  (only constant PRAGMA/SELECT 1); no blocking calls in async paths;
  Dockerfile runs non-root with HEALTHCHECK.
- R10 honesty fix is correct at all three layers (engine nested claims,
  route provenance, page copy) with a focused regression suite; the
  `_china_provenance` helper centralizes the rule.
- Alembic chain is clean (15 revisions, single head 015); the (year,week)
  index work is evidence-backed; the DuckDB decision was closed with
  benchmarks rather than vibes.
- Test suite: 31 files, 692 tests, ruff CI-enforced, e2e API contract specs.
- Zero TODO/FIXME/HACK markers and zero stray print() in core - unusual and
  commendable.
